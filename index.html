01. Development Environment & Stack Overview

Setting up a local development stack is essential for building, testing, and debugging server-side applications offline before deployment.

  • Server-Side Execution Environment: PHP code cannot be executed directly by client browsers. It requires a local web server (Apache) to interpret scripts.
  • Relational Storage Link: Local database engines allow fast query iteration and schema design without live cloud dependencies.
  • Integrated Toolchain: Combining Apache, MySQL, VS Code, and reverse engineering utilities builds a robust local pipeline.

02. Web Server & Database Engine: XAMPP

XAMPP is an open-source local server stack bundling Apache, MySQL/MariaDB, PHP, and Perl into a unified environment.

  • Apache HTTP Server: Intercepts incoming HTTP requests from the browser, processes PHP scripts, and returns standard dynamic HTML.
  • MySQL Database Engine: Manages relational data storage, executes SQL queries, and enforces foreign key constraints.
  • Internship Role: Served as the foundation for local backend testing, eliminating external hosting dependencies during development.

03. Database GUI Administration: phpMyAdmin

phpMyAdmin provides a clean web-based graphical interface for inspecting, managing, and querying MySQL databases visually.

  • Visual Schema Management: Allows visual creation of databases, tables, column data types (`INT`, `VARCHAR`), and primary key bindings.
  • Direct Query Execution: Enables running raw SQL queries directly in the UI to verify dynamic inserts and updates.
  • Internship Role: Used to design the data database schema and verify table updates in real time.

04. Code Editing Environment: Visual Studio Code

VS Code is a lightweight, extensible code editor configured with PHP linters and syntax checkers.

  • PHP Extensions & Linting: Highlights syntax bugs, unclosed brackets, and missing variables in real time.
  • Integrated Terminal: Used for directory navigation, command execution, and monitoring server logs.
  • Internship Role: Main editor for authoring modular PHP files (`conn.php`, `webpage.php`, `update.php`) and HTML templates.

05. Asset Extraction & Mirroring: HTTrack

HTTrack Website Copier is an offline browser utility used to mirror and extract static website structures and assets.

  • Template Deconstruction: Captured pre-rendered public layouts to examine CSS styling and structural patterns.
  • Static-to-Dynamic Conversion: Converted hardcoded HTML templates into reusable PHP components (`header.php`, dynamic forms).
  • Workflow Acceleration: Bypassed repetitive client-side CSS design to concentrate development time on backend security and database logic.

06. Centralized Database Connection

Establishes a single centralized connection script (`conn.php`) included across all endpoints via include('conn.php').

<?php
$server   = "localhost";
$username = "root";
$passwd   = "";
$dbname   = "data";

// Establish link to MySQL database
$conn = mysqli_connect($server, $username, $passwd, $dbname);

if (!$conn) {
    echo "Connection failed: " . mysqli_connect_error();
}
?>

08. Dynamic Record Fetching (view.php)

Queries dynamic rows using SELECT * and renders HTML table rows in a loop.

09. Targeted Record Mutation (update.php)

Modifies existing records by primary key (`id`). Replaced incorrect bracket syntax with clean PHP variable binding.

<?php
include('conn.php');

if (isset($_POST['update'])) {
    $id   = $_POST['id'];
    $name = $_POST['name'];
    $age  = $_POST['age'];
    $dept = $_POST['dept'];

    // Clean variable binding without bracket errors
    $update = mysqli_query($conn, 
        "UPDATE student SET name='$name', age='$age', dept='$dept' WHERE id='$id'");
}
?>

10. Security & Defense Best Practices

  • Preventing SQL Injection (SQLi): Transition from string concatenation to PDO/MySQLi Prepared Statements with bound parameters (`$stmt->bind_param()`).
  • Cross-Site Scripting (XSS) Defense: Sanitize dynamic output with htmlspecialchars() before rendering dynamic strings into HTML markup.
  • Credential Protection: Store user passwords securely using password_hash() and verify them using password_verify().
